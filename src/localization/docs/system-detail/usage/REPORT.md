# 로컬 Qwen 사용량과 이 컴퓨터의 튜닝 기록

2026-09-14 KST. 모델은 기존 `qwen3-coder:30b` / Qwen3-Coder 30.5B A3B Q4_K_M을 사용했다. 모델 가중치의 Ollama source blob은 `696dd86adb1ed54f138e199c0278a412fbcb30b997a880d4bf3e04a6dd5b7792`로 유지되었다.

## 적용한 설정

- PC: RAM 약 31 GiB(32 GB급), NVIDIA GeForce RTX 3060 12,288 MiB.
- 로컬 helper `/home/paik/.codex/tools/local_qwen.py` 기본 컨텍스트: **4,096 → 8,192**.
- Ollama 모델 기본 `num_ctx`: **8,192**. 모델 기본 temperature는 **0.2**로 통일했다. helper는 기존에도 0.2를 요청했다.
- 긴 파일은 `--context 16384`를 명시해 사용한다. 자동으로 더 큰 창을 선택하거나 메모리에 따라 서비스 설정을 계속 변경하지 않는다.
- 기본 출력 상한은 기존 700토큰을 유지한다. 요약은 이번 작업에서 450토큰, 정확한 문자열 추출은 200토큰으로 제한했다.
- 모델·provider 교체나 서비스 재시작 없이 기존 로컬 모델 설정을 갱신했다. 원본 GGUF import 명령은 동일한 기존 blob을 재사용한 것으로 확인했다.
- helper 결과에 요청 컨텍스트, 출력 상한, load/prompt/generation 시간과 생성 토큰/초를 추가했다.
- 기존 helper 백업: `/home/paik/.codex/tools/local_qwen.py.before-8k-20260914`.
- 기존 4K/temperature 0.6 파라미터로 복원한 모델 별칭: `qwen3-coder:before-context-tuning`.

## 비교 시험

같은 YAML의 backend와 센서별 `stamp_semantics`를 추출했다. 아래 warm 요청은 컨텍스트별 두 번째 실행이며 같은 prefix cache를 재사용할 수 있다. 각 1회 값이므로 일반적인 응답 시간 보장은 아니다.

| 컨텍스트 | 실제 입력 | 생성 | warm 응답 | 관측 최대 GPU 사용 |
|---|---:|---:|---:|---:|
| 4,096 | 669 | 66 | 2.491초 | 11,179 MiB |
| 8,192 | 669 | 66 | 2.649초 | 11,194 MiB |
| 16,384 | 669 | 66 | 2.786초 | 11,190 MiB |

해당 비교에서 OS `MemAvailable`은 약 23 GiB 이상이었다. 이 값은 회수 가능한 파일 캐시도 포함하므로 사용하지 않는 물리 RAM만을 뜻하지 않는다. GPU 여유는 약 1 GiB 수준이어서 ROS/화면 작업과 함께 쓸 때 컨텍스트를 무제한 늘리거나 동시 추론을 늘리는 설정은 적용하지 않았다. Ollama가 컨텍스트에 따라 CPU/GPU 배치를 조정하므로 VRAM 사용이 컨텍스트에 비례하지 않을 수 있다.

8K/16K로 크기를 바꾼 직후 요청은 모델 재적재를 포함해 약 22초였다. 튜닝 후 실제 RDDF 함수 72줄을 8K 기본값으로 읽는 시험은 실제 입력 1,028토큰, 생성 25토큰이었고, 반환한 상태 문자열 5개를 Python AST에서 추출한 정답과 자동 비교해 일치함을 확인했다. 해당 첫 요청 46.751초 중 모델 load 35.973초, prefill 9.753초, 생성 1.013초였으며 생성 속도는 24.67토큰/초였다. 긴 유휴 후 첫 요청과 재사용 요청의 시간을 구분해야 한다.

8K/16K 창 전체를 가득 채운 장문 정확도·장시간 부하 시험은 하지 않았다. 현재 결정은 메모리 여유, 설정 창이 실제로 적용됐는지, 짧은 동일 입력과 실무 파일 구간의 동작을 확인한 범위에 근거한다.

초기 두 시험은 요청에서 잘못된 키 이름 `timestamp_source`를 사용하여 요약이 부정확했고 하나는 출력 상한에 도달했다. 원장에는 실패·잘림을 보존했으며 위 비교에서 제외했다.

## 토큰 절감: 실측과 대리 지표

아키텍처 조사에서 Qwen 요약 요청 **9회**, 로컬 입력 **5,842토큰**, 로컬 생성 **1,250토큰**을 실측했다. 컨텍스트 튜닝 시험은 별도 기록하며 절감 실적으로 더하지 않는다. 이전 대화의 연결 확인 요청도 이 작업 원장에 포함하지 않았다.

동일한 텍스트 인코딩 `o200k_base`로 아래 비교를 재현할 수 있다. 이는 실제 Codex 모델의 청구 토큰을 측정한 값이 아니다.

1. 기준 입력: 로컬 helper에 제공한 소스 구간 원문.
2. 요약 입력: Codex로 돌려받은 요약을 포함한 JSON 결과.
3. 원문 − 요약 JSON 합계: **2,618토큰 감소**.
4. Codex가 실제로 다시 읽은 원문 6구간: **3,072토큰** 추가.
5. 이 제한된 비교의 재검토 차감 결과: **−454토큰**, 즉 입력이 오히려 454토큰 증가.

따라서 **이번 작업에서 순 OpenAI 토큰 절감이 있었다고 주장하지 않는다.** 위 값에는 도구 호출 조율, 관련 파일의 다른 검사, 추론, 최종 문서 작성, 누적 문맥과 캐시, benchmark 결과를 읽는 비용이 포함되지 않는다. 요청 수가 줄었다거나 Qwen이 생성한 1,250토큰만큼 OpenAI 생성 토큰이 절감됐다는 뜻도 아니다. 실제 청구 절감량·금액·절감률은 측정하지 않았다.

일부 요약은 초기화 실패의 원자성, GPS timestamp 의미, 정적 GPS TF 비활성화와 GPS 기능 활성화 관계, encoder yaw 입력 등을 잘못 해석했다. 문서에는 해당 추론을 채택하지 않았다. Qwen에는 파일/로그의 제한된 구간에서 명시적 사실을 추출하는 일을 맡기고, 복잡한 제어 흐름·아키텍처 결정·최종 검증은 Codex에서 처리한다.
